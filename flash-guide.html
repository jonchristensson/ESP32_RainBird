Flash MicroPython firmware

One-time only

If you've already flashed MicroPython to this exact board and haven't reflashed Arduino or anything else since, skip to Step 2. Otherwise, do this once.

1a — Find your COM port

1

Plug the ESP32 into USB. Open Device Manager (Win+X → Device Manager) and expand Ports (COM & LPT). Look for Silicon Labs CP210x or CH340 — the number after COM is your port.

Quick alternative — run in PowerShell: 
Get-PnpDevice -Class Ports | Where-Object Status -eq 'OK' | Select-Object FriendlyName
You'll see something like: Silicon Labs CP210x USB to UART Bridge (COM4)
Replace COM4 in all commands below with your actual port number.

1b — Install esptool

2

Run in PowerShell (Python 3 must already be installed):

pip install esptool

1c — Download the firmware

3

Download ESP32_GENERIC-20241129-v1.24.1.bin from the MicroPython downloads page:

https://micropython.org/download/ESP32_GENERIC/

Save it somewhere easy to reference — e.g. your Downloads folder or the project root.

1d — Erase the flash

4

This wipes the board completely. Run from the folder containing the .bin file (or use the full path):

esptool.py --chip esp32 --port COM4 erase_flash
Hold the BOOT button on the ESP32 while this command starts if it fails with "Failed to connect." Release once you see "Connecting…" in the output.

1e — Write MicroPython

5

Flash the firmware at the correct address (0x1000):

esptool.py --chip esp32 --port COM4 --baud 460800 write_flash -z 0x1000 ESP32_GENERIC-20241129-v1.24.1.bin

This takes about 20–30 seconds. You'll see a progress bar. When it says "Hash of data verified" and "Leaving…", it's done.

Expected output ends with:
Hash of data verified.
Leaving...
Hard resetting via RTS pin...
2

Create secrets.py

Required every new machine

The project keeps credentials out of git in a gitignored secrets.py file. You need to create it from the template and fill in your values.

2a — Copy the template

1

In PowerShell, from the project root:

Copy-Item secrets_template.py secrets.py

2b — Fill in your values

2

Open secrets.py in any editor and fill in each field:

Field What to put here
WIFI_SSID Your home WiFi network name (case-sensitive)
WIFI_PASSWORD Your WiFi password
OWM_API_KEY Your OpenWeatherMap API key. Get a free one at openweathermap.org/api — the free tier allows 1,000 calls/day; this firmware uses ~192/day.
LATITUDE Your location's latitude in decimal degrees (e.g. "36.4620"). Find it on Google Maps: right-click your house → the first number shown.
LONGITUDE Your location's longitude in decimal degrees (e.g. "-116.8666"). The second number from Google Maps. Include the minus sign if west of the prime meridian.
OTA_PASSWORD A strong password you choose for over-the-air updates via WebREPL. Write it down — you'll need it to push file updates over WiFi later.
New OpenWeatherMap API key? Free keys are active within a few minutes but can take up to 2 hours. If you get HTTP 401 errors in Step 4, wait a bit and try again.

2c — Confirm it's gitignored

3

Double-check that secrets.py will never be committed:

git status

secrets.py should not appear in the output. If it does, something is wrong with .gitignore — stop and fix that before proceeding.

3

Upload project files to the device

Required after every flash

3a — Install mpremote

1
pip install mpremote

3b — Upload all files

2

From the project root directory, run this single command (replace COM4 with your port):

mpremote connect COM4 cp boot.py main.py config.py network.py weather.py irrigation.py status.py ota.py webrepl_cfg.py secrets.py owm_ca.pem :
The trailing colon (:) means "copy to the root of the device filesystem." Don't omit it.

You'll see each filename printed as it uploads. The owm_ca.pem certificate is the largest file and takes a few extra seconds.

3c — Reset the device

3

After upload completes, reset the board so it boots into the new firmware:

mpremote connect COM4 reset

Alternatively, press the EN (reset) button on the ESP32 board.

4

Verify on serial

Required

4a — Open the serial monitor

1

Connect to the device's serial output at 115200 baud:

mpremote connect COM4 repl

Then press EN (reset button) on the ESP32 to trigger a clean boot and see all startup messages. Press Ctrl+] to exit the REPL when you're done.

You can also use any serial terminal (PuTTY, Thonny, VS Code Serial Monitor) at 115200 baud on the same COM port.

4b — What you should see

2

On a clear day with no recent rain, expect output like this:

=== ESP32 Rain Sensor booting === Status: None -> error WiFi: connecting to MyNetwork... WiFi: connected, IP= OTA: WebREPL started on port 8266 Weather: recent rain (3h) = 0.000 in Weather: forecast rain (12h) = 0.000 in Irrigation: allowing — rain_3h=0.000" forecast_12h=0.000", relay de-energized Status: error -> ok

After the first cycle the device runs a weather check every 15 minutes. You'll see the Weather and Irrigation lines repeat on each cycle.

4c — Checklist before moving to integration test

3
  • Serial shows "WiFi: connected, IP=…" — WiFi credentials are correct and device can join the network
  • Serial shows "Weather: recent rain…" lines — API key is valid and device reached OpenWeatherMap over HTTPS
  • Serial shows "Irrigation: allowing…" or "Irrigation: BLOCKING…" — relay logic is running
  • Status reaches "ok" (solid LED) on a clear day, or "rain" (slow blink) if thresholds are exceeded
  • No "Traceback" or "Error" lines in output

4d — Troubleshooting

4
SymptomLikely cause & fix
Stuck on "WiFi: connecting…" then error after 30s Wrong SSID or password in secrets.py. Re-upload after fixing.
Weather lines never appear / OSError on HTTPS API key invalid or not yet active (new keys take up to 2 hours). Check key at openweathermap.org. Also verify lat/lon are strings in quotes.
SyntaxError or ImportError in traceback A file wasn't uploaded. Re-run the mpremote cp command from Step 3b.
Fast-blinking LED, no serial output Device is stuck in error state. Open REPL and check for exception: mpremote connect COM4 repl
esptool "Failed to connect" Hold BOOT button on the ESP32 while the command runs, release when you see "Connecting…"
